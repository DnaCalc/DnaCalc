# Excel model-only tables in VertiPaq

Microsoft publishes the Excel workbook Data Model part and its storage format. MS-XLDM
revision 8.3 specifies the backup stream (§2.1), column data and dictionaries (§2.3),
XML column metadata (§2.5), and hybrid run-length and bit-packed encoding (§2.7.3).
Column values come from the identifiers in each `.idf` column and the matching dictionary
or value encoding. Physical row order can differ from worksheet order.
[MS-XLSX §2.1.6](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-xlsx/2e8ec4ac-000c-46e0-a1a7-8f7cb5b4e862),
[MS-XLDM 8.3](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-xldm/),
[column storage](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-xldm/4d3887f8-64c8-4dbd-9a02-e4e95e64bfed)

PBIXRay 0.15.5 reads the XLSX stream and its column XML. Its source documents two
compatibility details relevant to a Rust reader. The per-file Xpress wrapper uses
16-bit sizes, and some Excel files have stale trailing RLE slots after the declared
record count. The spike uses the library for archive extraction, metadata and strings,
and implements one single-segment identifier decode in Python.
[PBIXRay 0.15.5 source and MIT licence](https://github.com/Hugoberry/pbixray/tree/c5da940b45d2806c8f8d3e109f0d1909117a7db0),
[format provenance](https://www.pbixray.com/provenance/),
[RLE and bit-packing](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-xldm/ef29562d-2334-472d-8228-aca5cbf7d0dc)

## Read-only Linux spike

The Excel 16.0.20527 M4 job saved `m4-model-only.xlsx` after deleting the source
ListObject. The retained input is
`dnacalc-evidence/excel/pivot-m4-20261108/files/m4/m4-model-only.xlsx`.
The workbook SHA-256 is `4bbb5885acc3ed11e0703fa197db64e6b2b169d7ca47f686b497c54129bc4585`.
It has zero worksheet table parts and a 77,824-byte model part with SHA-256
`9e8132aa0c4bd6fdd783834984bbe2876535a57bc105591001e7d32a0c785352`.
[M4 provenance](../../crates/calc-host/tests/fixtures/pivot_cube/README.md),
[fixture authoring job](../../tools/excel-session/pivot-job.ps1)

Run [decode_model.py](vertipaq-2026-11-22/decode_model.py) on that retained workbook
in a Python 3.13 environment with `pbixray==0.15.5`.

```sh
python docs/research/vertipaq-2026-11-22/decode_model.py /path/to/m4-model-only.xlsx
```

On dna-firehorse (Linux x86-64), the spike decoded one table, seven rows and three
columns. All 21 entries agreed with PBIXRay and all seven rows matched the M4 job's
authored inputs, including all seven binary64 Amount encodings. A separate control
decoded one valid segment and refused two malformed segments. The retained Excel
observations after the source deletion report a row count of 7 and a total of 135.3.
[Retained M4 observations](../../crates/calc-host/tests/fixtures/pivot_cube/stages.tsv)

The Amount column uses `BaseId=-2` and `Magnitude=10`. Dividing the adjusted ID by
the magnitude gives the authored amounts, including the exact encodings for 0.1 and
0.2. The published `PropertiesValueDictionaryType` description instead gives
multiplication. The observed scaling applies to this witness. Broader value-encoding
parity remains with dc-8wp.20.
[MS-XLDM value dictionary](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-xldm/c89d829a-a0ee-4d3b-bc9a-b8ef44684cc6)

## Product work owned by dc-8wp.20

CalcDoc currently reads model table names and measure expressions. CalcHost builds
the initial snapshot from worksheet tables and replaces the loaded snapshot at
open. A model-only load needs a bounded Rust decoder in CalcDoc that publishes
`ModelSnapshotProvenance::DecodedModel`, then CalcHost must retain the admitted
rows. Model-pivot admission also needs to accept decoded provenance where it
currently requires worksheet provenance. Validate nulls, dictionary encodings and
multiple segments on captured inputs before admitting those layouts. The existing
CalcEngine cube evaluator can consume rectangular decoded rows through the shared
snapshot.
