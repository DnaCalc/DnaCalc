The Skinning Guide

A DNA Calc workbook is an Excel workbook. What you see around it is replaceable: views are compiled engines, skins are data, pages are component trees, and one contract sits underneath them all. This guide shows how that is built, how it reaches the calculation engine, and how to make a skin of your own.

01

The idea in one picture

There is one workbook, one selection and one undo history. Everything on screen is a way of looking at them.

A view is a compiled engine

A Rust crate that implements View. It is given a Session and nothing else: no shell type, no carrier, no other view. Classic, Inspector, Notebook and App exist; Model map is designed.

A skin is data

A dna.skin/1 JSON manifest. It restyles and rearranges the views that exist. It cannot add behaviour, because it holds no code.

A page is a component tree

A dna.page/1 flow layout of standard components, each bound to workbook cells. One grammar, one renderer.

One contract underneath

calc-skin is the only thing page code and host code share. It reaches no engine, no file codec and no UI toolkit.

02

Philosophy

Four rules shape every type in the contract. A skin author meets all four within the first hour.

No more than Excel

The engine calculates what Excel calculates and nothing else. A view may show a workbook in a new way; it may not give it a new meaning. Every change to the model is an operation Excel itself can express. A notebook cell is a worksheet cell. A map box is a named cell on a visible sheet.

Honesty about state

No value crosses the contract without saying where it came from. Shown<T> carries a Provenance; every answer carries a Coverage; every query takes a Budget. A component cannot draw a stale number as a fresh one, because the type does not let it lose the difference.

Model edits and presentation edits are different things

Moving a panel is not editing a spreadsheet. The contract keeps two revisions, Stamp.model and Stamp.view. A presentation change never advances the model revision, and the preview tells you which kind you are about to make before you make it.

No code in files

A workbook carries declarations: anchors, view documents, notes. Skins and pages are JSON with no scripts, no expressions, no HTML and no URLs. Opening a file runs nothing and fetches nothing.

Honesty, as types

These are the actual definitions in crates/calc-skin/src/workbook.rs. Seven provenances, two coverages, three kinds of evidence.

pub struct Shown<T> { pub value: T, pub provenance: Provenance }

pub enum Provenance {
    Empty,
    Literal,
    Calculated { calc: CalcGeneration },
    AsSaved,                                   // from the file; this engine has not calculated it
    External { source: String, observed_at: Option<u64> },
    Stale    { since: Revision, cause: StaleCause },
    Refused  { owner: String, reason: String }, // typed not-modelled refusal naming its owner
}

pub enum Coverage { Complete, Partial { done: u64, total: Option<u64>, why: PartialWhy } }
pub struct Answer<T> { pub stamp: Stamp, pub coverage: Coverage, pub body: T }

pub enum Evidence<T> {                        // what ran is never confused with what is inferred
    Observed    { observer: String, at: Stamp, body: T },
    Derived     { from: Derivation, at: Stamp, body: T },
    Unavailable { reason: String },
}
