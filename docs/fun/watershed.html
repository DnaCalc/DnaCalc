What this shows

Heterogeneous models from one workbook

Ptolemy II's central idea is that different parts of a system want different models of computation, and that a hierarchy of actors can give each part its own director while the parts still exchange values cleanly. A workbook already contains every one of these mechanisms; they are just never shown as such. This preview gives each its own director and draws the boundaries between them.

Eventstop level · RTD

Two RTD topics raise events: the clock at its rate, the market at random times. An event recalculates only its dependents: a price update touches Turbine and Finance and leaves the reservoir alone, which is exactly Excel's dirty-set recalculation.

TicksWeather, Reservoir · iterative calculation, one pass

State cells refer to themselves (z⁻¹): =MIN(Capacity, MAX(0, Level + Inflow − Release)) advances once per clock event.

ModalOperator · IFS over its own previous state

A mode cell remembers its state, so the guards have hysteresis. Each state has its own release rule, its refinement: a CHOOSE over three formulas.

IterationFinance · maximum 100, maximum change 0.001

Interest on average debt is the classic financial circularity: interest needs this period's debt, debt needs the repayment, the repayment needs interest. Excel's two iteration settings are the director's parameters; the view shows the settled values each tick, as Excel does.

SweepOutlook · a what-if data table

=TABLE(, Weather.RainMult) reruns the forward model for 25 rainfall multipliers and returns 25 level paths: the fan.

The RTD clock, as a spec

  • Topic =RTD("DnaCalc.Clock",, model, "tick") returns the tick number; every update is an event that recalculates the tick's dependents.
  • Control by cells the server reads: Clock.Run (TRUE/FALSE), Clock.Rate (ticks per second), Clock.Step (one tick when changed), Clock.ResetWhen (a tick number or a condition cell such as Finance.Debt<=0).
  • Second topic =RTD("DnaCalc.Market",, "power.price", seed): a seeded random walk at its own rate, so the run is repeatable and differential tests against Excel compare tick by tick.
  • Engine test (bead dc-hul4): the same event sequence must give the same cells in Excel and in DNA Calc, including resets, throttling and recalculation order under RTD.

Only what Excel does

The rule: the engine does what Excel does and nothing more, and the same workbook runs in Excel. Every mechanism in this model is plain Excel: RTD, iterative calculation with its two settings, IFS and CHOOSE over a self-referencing cell, and data tables. The view is built only from what Excel also exposes, so it can run as a skin in DNA Calc and as an add-in in Excel.

  • Boxes and wires: the workbook's defined names and their formulas; precedents as Excel gives them (Range.DirectPrecedents, Range.Precedents), and in DNA Calc the matching host calls that already exist (dc-gf0).
  • The firing order shown: worked out by the skin from the dependency graph (a topological order), not reported by the engine.
  • What recalculated, and why: values compared before and after each calculation event (Application.AfterCalculate, Worksheet_Calculate), and the RTD topic or edit that the view itself saw arrive. No cause tracking inside the engine; where several things land in one recalculation, the view says so.
  • Iteration: the director shows Excel's settings (maximum iterations, maximum change) and the values before and after, not the engine's internal iteration count.
  • Layout: a part stored with the workbook that Excel keeps and ignores, as in the linked-boxes note (dc-lvlj).
