## 1. Must-fix

- **M1 — §1.2, decision 4(a): absence of relative references does not justify one memoised name result.** `ROW()`, `RAND()` and a stateful UDF need no relative references, yet sharing their result can change caller semantics or call counts. Microsoft documents evaluation per referring formula and no evaluation of unused names even on full calculation ([name evaluation](https://learn.microsoft.com/en-us/office/vba/excel/concepts/excel-performance/excel-improving-calculation-performance#formula-and-name-evaluation-circumstances)); today's evaluator executes the name block at each use (`crates/calc-fml/src/eval/run.rs:1000–1015`).
  Keep first-class `NameId` nodes, but separate definition identity from evaluation instances; memoise only when purity, caller independence and context equivalence establish that reuse is unobservable. Include scenario/input-view identity: even `=Sheet1!$A$1` differs between data-table substitutions. Preserve reference/closure results until the consumer requests values.
- **M2 — §0.3 overstates what is unmeasured and conflates placement routes.** Relative-name wrapping is implemented and backed by recorded Excel observations: `crates/calc-fml/src/eval/compile.rs:1254–1259`, `tests/acceptance/l1.rs:634–645`; R1C1 INDIRECT wrapping is measured separately (`tests/acceptance/dc_51ka.rs:253–266`, both test paths under calc-fml). The generic comment in `reference/mod.rs:184–186` is incomplete evidence.
  Carry placement and edit semantics with templates; do not infer them merely from `AxisRef::Relative` or impose a single wrap/#REF rule. Names also have a different structural transform: relative offsets stay unchanged, absolute axes move (`crates/calc-fml/src/reference/transform.rs:25–30,386–397`). Decision 8 should measure missing routes and regress existing ones.
- **M3 — S2 and §5.1 give an invalid general insertion bound/cost.** A zero-reference block spanning the insertion needs two extents, already exceeding `1 + 2r` for `r=0`. `Sheet1!A200 = Sheet2!$A$100` changes when row 50 is inserted on Sheet2, although its block is on another sheet and neither endpoint straddles row 50. Absolute references move too (`crates/calc-fml/src/reference/transform.rs:6–11`).
  Restrict the offset argument to same-sheet relative references; count the source split, all affected reference occurrences, range endpoints and grid-edge clipping. Index absolute and cross-sheet targets as well as relative ones, and preserve the separately measured name and 3-D rules (`transform.rs:19–30`). Do not label `1 + 2r` a settled general result.
- **M4 — §§1.1/1.3/1.7 need distinct read observations and recalculation dependencies.** Routing every VBA Range read through the ordinary dynamic-edge mechanism makes Excel-incompatible dependencies. The retained probe reads Z1 internally, changes Z1 to 31 and leaves B12 at `4:30`; only explicit B12 calculation produces `5:31` (`crates/calc-vba/tests/fixtures/excel-recalculation/probe.bas:37–39,147–156`; `observations.json:348–361,404–417` in that directory).
  Give the read context an explicit purpose: ordinary formula dependency, UDF callback observation, or diagnostic read. Keep the information needed for coherent execution without automatically making hidden VBA reads dirty-propagation edges or forcing their prerequisites. Apply measured rules to argument references separately; the current bridge (`crates/calc-fml/src/eval/run.rs:1885–1891`) is not evidence of Excel scheduling semantics.
- **M5 — §1.1's RTD-in-VolatileServices rule loses external invalidation.** “Never dirty non-volatiles” cannot apply to RTD updates and their dependent formulas. RTD delivers topic/value updates ([RefreshData](https://learn.microsoft.com/en-us/office/vba/api/excel.irtdserver.refreshdata)); the existing plan explicitly separates external updates from volatility (`docs/plan/DNA_CALC_REIMPLEMENTATION_PLAN.md:418,425,562`).
  Retain clock/seed as tick services; model RTD and async completion as sequenced external-update operations with provider/call generation, snapshot identity, stale-completion rejection and targeted invalidation. Record these events for replay instead of relying solely on a per-tick effect tape.
- **M6 — §1.3 and §5.2D must preserve calculation-command scope.** “No dropping in any Excel mode” must mean no dropping from the command's obligation, not completion of every dirty node. Automatic Except Tables is already implemented (`crates/calc-host/src/recalc.rs:74–82`); sheet/range calculation can intentionally leave other work pending ([calculation modes and commands](https://learn.microsoft.com/en-us/office/client-developer/excel/excel-recalculation#calculation-modes-commands-selective-recalculation-and-data-tables)).
  Define demand from mode, command, target and forced-vs-dirty evaluation before interest scheduling; retain deferred dirty state. Add range calculation and table deferral to the request contract. A pending prerequisite outside an allowed calculation scope cannot be evaluated merely to satisfy an unconditional “no dirty backward cone” rule; represent the resulting freshness accurately.
- **M7 — §1.3's edit merging and §1.7's code leases do not protect mutable VBA effects.** A UDF can mutate Static/module state, then have its publication rejected after an edit; retrying it changes observable state again. Leases protect code lifetime, not rollback of effects (`docs/plan/VBA_UDFS.md:6–7,22–25,78–80`).
  Serialize conflicting edits/reload with the active effectful unit, or specify a real transactional state mechanism; preserve a suspended activation rather than replaying it. Validation/retry for pure work and admission/commit for effectful work require different rules. Atomic publication alone is insufficient.

## 2. Missing decisions and seam pressures

- **Notebook name evaluation:** specify an explicit caller/anchor and evaluation request for caller-sensitive names, plus an observation policy for unused or effectful names. Switching skins or inspecting a name must not silently create extra UDF/RAND evaluations. Decide whether runtime switching changes only the projection or migrates formulas/references; those are different operations.
- **Binding watches beyond sheet shadowing:** name deletion/rename, tables sharing the namespace, UDF registration replacing unresolved calls, and sheet-order changes need targeted rebinding. A single registry generation in every plan key recreates broad cache churn; use per-binding versions plus negative lookup watches. Table fallback already exists at `crates/calc-fml/src/eval/compile.rs:1228–1238`.
- **Browser responsiveness:** step 3a must actually return to the worker event loop between slices; a synchronous loop that drains a Rust inbox cannot receive `postMessage`. Include resumable scans and distinguish atomic publication from uninterrupted execution for SCCs/data tables. Test delivery of an interest/edit message during a long calculation, not only budget arithmetic (`apps/dna-calc/src/worker.rs:60–90`).
- **Facts versus invalidation policy:** S1's “no Format facet” must not remove format/fact versions from read validation. CELL volatility does not prove that a result computed against old formatting may commit after a format edit. Record observed fact versions while separately deciding, from Excel evidence, which edits trigger calculation.
- **Wire consistency across edits:** tiles need workbook/session identity, model revision, interest version and publication sequence, with dictionary generation and an ordering rule relative to edit receipts. Otherwise a delayed pre-insertion tile can repopulate a valid coordinate with the wrong cell. Define snapshot/reset recovery and disposal of old dictionaries, not just sequence-gap detection.
- **Save and undo during partial calculation:** specify which committed revision save captures, how pending/file-cached values and recalculation flags are written, and how undo restores authored state without treating effects as reversible. Codec round trips must retain array/data-table kinds, unsupported tokens/metadata and untouched bytes; “blocks write back as shared groups” needs eligibility rules.
- **COM construction and ownership:** `windows-core` supplies COM implementation machinery, not the specified `.tlb` generation pipeline ([crate documentation](https://github.com/microsoft/windows-rs/blob/master/docs/crates/windows-core.md)). Choose descriptor-to-IDL/MIDL or [CreateTypeLib2](https://learn.microsoft.com/en-us/windows/win32/api/oleauto/nf-oleauto-createtypelib2); specify HRESULT/retval, optional/default arguments, BSTR/SAFEARRAY ownership, apartment/reentry and surviving Range objects across workbook close/reload.
- **Actual runtime composition:** decision 1's API-only Cargo edge does not explain how either app obtains an interpreter/JIT implementation. Specify the provider factory and native link/load versus browser instantiation, ABI version negotiation and allocator ownership; do not restore a hidden runtime dependency through the neutral descriptor crate.
