# DNA Calc target architecture — GPT-Astra 6

## 1. Abstract architecture

### Contract and ownership

Build around a versioned calculation domain, an explicit formula execution contract, and a functional model usable by every skin. Storage, scheduling, execution strategy and presentation may change independently; Excel semantics may not.
This draft uses the complete briefing and six evidence files, plan §§2–8, and read-only inspection of DnaCalc-review at **5a9348be4260ad0d7980599f20866de22552ff62**. Source paths below refer to that checkout. OxVba findings are attributed to risk-vba.md; its repository was not accessed. No builds or measurements were run. Audit memory/allocation figures remain estimates.

Five invariants:

1. **One authored authority.** A host owns immutable document roots and an ordered operation journal. Calculation state is derived; UI mirrors, file caches and extension state cannot become alternative authored workbooks.
2. **One semantic execution route.** Formula parsing, binding and execution belong to CalcFml; built-in semantics belong to CalcFunc. The engine owns dependency analysis, scheduling and optimisation. OneCalc invokes the same formula route with a small provider and no graph.
3. **Identity, position and storage location differ.** A logical participant survives repartitioning; an Excel address follows reference and structural-edit rules; a local slot is disposable.
4. **Freshness requires evidence.** A published value has its input, binding, numeric and effect context. Worksheet errors are calculated values; missing capability, cancellation and infrastructure failure are separate outcomes. A retained answer never silently becomes fresh.
5. **Optimisation preserves observations.** Argument demand, coercion, operation/store order, reference reads, error identity, spill ownership and effects constrain every optimisation, including parallel reductions.

An authored command prepares document and engine changes against one base revision, reserves required storage, then commits under one mutation owner without extension callbacks. Calculation is scheduled afterwards; cancelling it does not undo the edit. Undo stores inverse structural/model patches, not a command to reconstruct the entire engine.
Save pins an authored root and a result view. Fresh caches require matching validity; stale/file caches follow an explicit preservation/omission policy. Unknown package parts retain provenance, but an edit that may invalidate their references needs a fidelity diagnostic or refusal. These rules cover both xlsx and xlsb; source preservation is not a second live model.

### Explicit contexts at the boundaries

Contexts are bundles of narrow services, not a universal mutable host object. Immutable snapshots can cross threads; mutable readers, scratch and invocation state are owned by one evaluation task.

| Boundary | Supplier and explicit contract |
|---|---|
| Platform → host | App composition supplies PlatformServices: clock, random/effect provider, external snapshots, application/file identity, font metrics, extension admission, executor and available capabilities. Resolve current-host locale here. Browser and native adapters implement the same contracts. |
| Host → engine | CalcRequest carries DomainSnapshot, SemanticContext, callable-registry snapshot, workbook-fact providers, RecalcPolicy, DemandSet and ExecutionPolicy. Semantic facts have versions; clock samples are effects, not mutations of the semantic environment. |
| Engine/OneCalc → CalcFml | FormulaEvaluationContext carries semantic context, binding catalogue, reference reader, tracked fact queries, callable bindings/invoker, effect service, observer, budget and cancellation. The instantiated formula supplies the sole caller identity. OneCalc supplies fixtures and explicit unsupported services; the engine supplies readiness and dependency tracking. |
| CalcFml → CalcFunc | FunctionServices contains numeric operations, locale comparison/coercion services, caller, reference-value/visibility access, reference-text resolution, NumberTextService, callable invocation and time/random access. CELL asks semantic questions such as prefix or width-in-characters; it never receives CSS, font tables or a skin object. CalcFml adapts this bundle once. |
| Codec ↔ model/host | CodecContext supplies format/function spelling conventions and resource policy. Load produces typed model records plus opaque source spans; save consumes a pinned model and provenance-aware SaveValueView. No engine dependency or live XML interpretation. |
| Host/model → skins | Versioned commands, capability descriptions, bounded queries, projection deltas, view-state handles and focus requests. The platform adapter handles DOM, clipboard and files. Skins receive no engine or mutable workbook access. |

Separate **SemanticContext** (date system, compatibility, locale/collation identity, numeric policy and relevant settings), **BindingSnapshot** (names, tables, sheets and callable versions), and **EffectScope** (calculation, scenario, iteration and invocation identities). Changing one invalidates only its declared dependents.
Every context read yields a value and a dependency token, including reads of absence, formula text, visibility, style and application facts. Engine-supplied wrappers record these tokens automatically. A value-reader overlay for a data-table scenario cannot accidentally erase caller or workbook facts.
Unavailable services return CapabilityMissing with a feature identity; an empty optional value is reserved for a fact that is actually absent. Readiness is explicit: Ready, NeedDependency, PendingExternal or Fault. CalcFml exposes Complete, Suspended, Yielded, Cancelled and Failed steps without knowing a scheduler.

There is one formatting implementation, owned by CalcFml. Its FormatContext includes date system, locale, compatibility, palette and purpose: worksheet TEXT, General display, input conversion and invariant file serialization are distinct purposes.
The host resolves base style, dimensions and font metrics once into CellPresentationFacts. Formula facts and displayed projections consume the same source. Conditional-format overlays are separately identified: whether an Excel function observes base or effective formatting is a semantic rule, not an accidental dependency on rendered output. This also prevents a CF rule from recursively asking for its own presentation.
Formatting that affects calculation, including precision-as-displayed, produces explicit semantic dependencies and any required authored changes. View clipping and zoom never alter numeric inputs.

### Representations and the optimisation boundary

| Entity | Representation and invariant |
|---|---|
| Formula source | Lossless source handle plus a canonical relative-reference TemplateRecord. Preserve original spelling through source spans and sparse overrides. Invalid/unrecognised formulas retain their source and a typed diagnostic. |
| Formula region | FormulaRegion { template, domain, origin, binding_scope, member_ids, exceptions }. Fills/shared formulas store affine placement rules; edits split regions and add sparse exceptions. Legacy arrays, spills and what-if tables retain distinct ownership semantics. |
| Bound plan | PlanKey = template + formula form + actual binding assumptions + callable versions + compilation-relevant semantic facts. A global workbook revision or clock tick is not a universal cache key. CompiledPlan is immutable; InstanceView computes placement without one boxed reference list per cell. |
| Values/results | Sparse pages for mixed cells; dense typed lanes for homogeneous tiles; dictionary UTF-16 text, explicit blank/missing/error tags, immutable array chunks and shared provenance records. Do not collapse blank, omitted argument, empty string and worksheet error into null. |
| Styles/formats | Interned StyleId/FormatId records, range/default assignments and bounded sparse overrides. Persistent indexes replace whole-Definitions copies and replaying all axis edits during lookup. CF contributes versioned overlays and aggregate participants. |
| Names/tables | Stable scoped NameKey/TableKey, binding versions and typed reference expressions. Relative names retain defining/calling context; unresolved names have absence watches. One name matcher serves binding and SHEET/INDIRECT; name matching is distinct from locale sort order. |
| Graph | One logical graph with typed facets: value, existence, shape, binding, order, visibility, format and external state. Affine region edges and rectangle/interval indexes compress regular dependencies; irregular edges use local adjacency chunks plus mutation overlays. Static reference dependencies and executed reads are distinct indexes of this graph. |
| Identity | DocumentKey plus stable entity keys; compressed ranges of member identities for regular formulas. Local NodeId remains slot + generation. PartitionId/lease identifies execution ownership, never permanent identity. No native usize or process pointer enters durable/wire identities. |
| Partitions | Bounded input/result/edge chunks with a directory mapping logical keys to owners. Partition boundaries need not equal sheets, formula regions, task sizes or viewport tiles. A1 coordinates retain Excel limits. Future non-grid participants have their own keys, not larger fictitious Excel cells. |

**A formula region is compressed storage, not one indivisible calculation node.** Each member remains individually addressable, observable and invalidatable. A fill B2:B1000001 = A2*2 has an affine edge family; changing A900 changes one member. A recurrence B3 = B2+1 cannot become an independent parallel vector merely because its syntax is shared.
The scheduler materialises bounded tiles and sparse exceptional members. A range edge describes a dependency relationship, not permission to regroup arithmetic. Initial region support can fall back to scalar execution using the same graph and evaluator.
Structural edits transform typed reference expressions and axis intervals. Keep an occurrence index over all syntax references, including inactive branches; observed reads alone are insufficient. Split regions where reference transforms cease to be affine. Stable identities do not make $A$1 immune to row insertion or turn deletion into a surviving reference.
Copy, move, insertion, deletion, table expansion and name rebinding remain different operations. References embedded in text for INDIRECT are governed by Excel text semantics, not rewritten as ordinary references. Materialise A1 source only for editing, FORMULATEXT, diagnostics and serialization.
Persistent axis maps must be compacted with snapshots accounted for; do not replace eager O(N) rewrites with an unbounded edit-history walk. Region compaction preserves member identities. Changed-sheet serialization can still require work proportional to that sheet.

Optimisation belongs in engine strategy modules: type-specialise tiles, vectorise independent cells, fuse pure operations, cache dependency footprints and reuse proven-valid results. Guards cover type, binding, numeric policy, aliasing, effects and shape; failure returns to the canonical CalcFml execution route.
JIT/native kernels must lower the same semantic operations, preserving source-span and call-site identities. Keep explicit order/store instructions where Exact requires them. Debugging selects a participant and tick, obtains a trace lease and deoptimises that participant if necessary; enabling one watch must not disable parallelism for the whole workbook.
Future Rust definitions and the web editor should construct the same participant/reference/operation model. Schema-versioned immutable records and arrays can later extend values through typed adapters; conversion to worksheet cells or Excel files must be explicit and loss-aware. Do not implement a second language or distributed product in this work.

### Recalculation, demand and publication

Use separate identities for authored revision, semantic/binding epochs, calculation tick, publication sequence and interest epoch. A viewport move changes only the last. A new calculation tick does not erase the distinction between when an unchanged value was computed and through which revision it remains valid.

~~~text
DemandSet { required_roots, interests[(selector, priority, interest_epoch)],
            completion_scope, freshness }
begin(snapshot, policy, demand) -> RecalcWork
update_interest(work, replacement_interest)
step(work, budget, cancel) -> Progress { publications, remaining, outcome }
Publication { snapshot, tick, sequence, changed_members,
              values, read_edges, shapes, reservations, validity }
~~~ 

**Demand** expresses required answers and completion obligations; **interest** expresses priority and delivery. Automatic mode still completes its required dirty work, with fairness for off-screen work. F9, active-sheet calculation, full calculation and dependency rebuild remain distinct commands. Manual mode does not calculate because a viewport subscribed.
Raise priority along the prerequisites of visible roots; schedule only ready tasks. Demand discovery itself must be incremental and indexed, not a full reverse scan on every scroll. Changing interests reprioritises queued work and cancels dispensable speculative tasks; it does not discard useful work or resample volatility.
Keep dirty membership and readiness incrementally, using chunk epochs/bitmaps. Until invalidation propagation is established, affected regions are conservatively pending. A query never recomputes the complete stale closure once per projected cell.

A completed independent participant can publish before the calculation finishes. A **publication unit** installs values, observed edges, shape/ownership changes and invalidations atomically. Validate its input/read/binding/effect versions and owner lease at commit; rejected candidates have no visible effect.
Each current result must have a dependency-closed validity certificate. A projection may mix current and explicitly stale cells, but it may not label a formula current after reading a stale prerequisite. Fresh queries wait for their required closure; old calculated provenance remains distinguishable from file caches.
Compress certificates as shared read-pattern descriptors and chunk/facet versions, with sparse exceptions; a new heap-allocated version vector per result would recreate the current memory problem.
Dynamic reads first establish readiness and subscriptions, then produce a result; a missing target also installs an existence watch. Newly discovered edges trigger cycle/readiness checks. Reads and dependency installation must be validated together so a concurrent change cannot fall between them.
Spills reserve their whole footprint and retire old children atomically. Pending shapes, overlapping spill candidates and their readers form a conflict group with deterministic arbitration. If an unknown shape could invalidate a candidate's read or reservation, delay publication or enlarge the group; a completed scalar evaluation alone does not prove settlement.
An iterative strongly connected component publishes only after its captured initialization/update/convergence contract finishes. Its internal order is not a priority queue. A data table runs ordered scenario overlays with separate scenario identity; scenario values never publish as base cells. Publish table output atomically initially; subdivide only when independence is established.
Workbook Calculate events and a completion receipt occur at the requested completion frontier, not at every UI publication. Saving during work either waits for its declared freshness scope or uses the explicit stale-cache policy.

Cancellation is cooperative and distinct from failure: request, stop spawning, drain activations, release reservations, retain valid published units. On an authored change, keep old results as stale where affected; reuse completed work only after validating its entire dependency/context certificate against the new snapshot.
Budget inside long range scans, array kernels and loops as well as between formulas. A cancellation check between million-element evaluations does not make the browser responsive. Exact continuations must preserve intermediate precision and floating-point state; inserting a binary64 store to yield would change the program.
Clock/random/external results use an EffectTape keyed by logical call-site and activation identity. Retries reuse effects. Stable seeded replay makes scheduling reproducible, but does not establish Excel's RNG or effect ordering. Where observable ordering is unresolved, constrain execution to a recorded/reference serial order; do not invent per-cell random streams and call them Excel-compatible.
Stateful UDFs, external side effects and apartment-affine calls are ordered execution groups. Do not speculate, duplicate or automatically retry them. Cancellation cannot retract an external effect already performed; report that outcome. A non-cooperative native extension prevents a universal bounded-cancellation promise.

### Concurrency and distribution

A session actor owns mutations and publication. It can remain !Send; immutable snapshots and task messages must be transferable. A persistent CPU pool evaluates coarse tiles with private frames. The browser coordinator yields to its message loop between bounded steps; additional workers are an execution adapter, not another evaluator.
Threads, wasm workers and future remote workers accept the same logical WorkPacket: snapshot identity, plan/content hashes, member ranges, prerequisite chunks, numeric/effect capabilities and an ownership lease. Native packets may borrow Arc-backed data; wire packets use explicit schemas and checked lengths.
Exact tasks run only on workers implementing the selected numerical target. An Intel worker cannot substitute its own x87 results for an AMD target; it needs a demonstrated equivalent backend or must decline the task.
Workers return candidates, never mutate authoritative state. Stale/duplicate replies are rejected by task identity and lease. Pure tasks can be retried after a worker dies; stateful extensions stay with their owner. No COM pointer, mutable runtime session or callable address crosses a remote boundary.
For distribution, maintain partition dependency summaries and per-domain completion frontiers; cross-partition reads request versioned chunks and register invalidation subscriptions. Snapshot retention, backpressure, result eviction and journal replay are required parts of the seam, not incidental cache details.
Start with one coordinator ordering authored operations across the domain; use a revision manifest for multiple workbooks. This prepares distributed calculation without promising distributed multi-writer transactions. Cross-partition cycles/spill conflicts are coordinated or colocated before publication; remote isolation does not make them independent.
A billion logical cells still require proportional information where results/dependencies are genuinely distinct. No task per cell, global slot-sized array or UUID hash-map per edge is acceptable. Measure metadata and resident result costs separately; compressed regular fills cannot establish performance for irregular billion-node graphs.

### Functional model and the worker protocol

The functional model has four separate stores: authored workbook, calculated facts, durable view layout, and ephemeral interaction state. View layout is model-owned and keyed by extensible SkinKey; selection, editor buffer, focus intent and dialog state also have model APIs. Skins only present and route.
Retain the plan's cell-backed layout model: stable block/placement IDs, ordinary visible backing cells and locator names, with versioned CustomXML for layout. One named-LAMBDA definition remains authoritative. On external Excel edits, reconcile locators; missing/ambiguous metadata produces orphan diagnostics, never reconstructed formulas from cached layout data.
Use CommandEnvelope { id, typed_payload, base_revision, source, undo_group, request_id }. Command descriptors expose availability with reasons, payload schema and presentation hints. A shell-level keymap and shared command browser expose every capability from every skin; a skin may add gestures but cannot own Excel rules.
Selection is semantic (ranges, participants, blocks); a selection of an entire sheet is not a request to hydrate it. EditSession has a registered SurfaceId and reference-picking contract rather than Cell/Bar/Notebook variants. FocusRequest targets a surface token and is fulfilled after mount acknowledgement, not a timer or a grid selector.
Queries describe cells/tiles, formula listings, dependency neighbourhoods, rule decisions, objects and diagnostics. Canvas receives keys/edges and model-owned placements; automatic pixel arrangement and SVG rendering stay in the presentation layer. New skins register descriptors, state schema and renderers; they do not add server request variants.

Use a versioned control envelope plus transferable TileBatch data: numeric/tag lanes, UTF-16/string dictionaries, style IDs, provenance codes, optional formatted text and sparse deltas. Format requested display tiles off the main thread; fetch source/provenance prose only for editors or inspectors.
UpdateInterest carries desired windows and acknowledged tile versions. TileDelta carries subscription/interest epoch, base sequence, new sequence and dictionary dependencies. Retain overlapping tiles; transfer entering/changed tiles; ignore obsolete-interest deliveries. Detect sequence gaps and refresh the affected subscription.
Bound each subscriber's queue. Coalesce projection updates and offer reset after a gap; command receipts and Calculate completion events remain ordered/reliable. The UI applies a complete batch before exposing reactive changes, then invalidates only changed tiles/cells. Transfer ownership is not end-to-end zero-copy; measure serialization and buffer construction too.
Reuse prefix-sum geometry, separate sub-tile scroll transforms from data updates, and key/pool visible render objects. DOM, canvas and WebGL remain renderer choices. Accessibility and browser tests consume a semantic interaction surface so rendering technology can change.

OneCalc gets a DOM-free FormulaSessionModel for formula, fixture, formatting, extensions and editor state. Shared editor/result/dialog/theme components and their interaction logic live once at its dependency ceiling. DNA Calc supplies workbook services to those components and includes the same formula-inspection capability; it never depends on the OneCalc app.

### Extensions, Exact and platform profiles

LAMBDA stays in CalcFml: immutable body, lexical captures and explicit reference/name scope. Worksheet display retains Excel's uninvoked-LAMBDA outcome; inspectors can expose a raw callable. Remote closure transport uses body identity and serializable captures, never a native pointer.
Resolve external functions during binding into CallBinding { provider, slot, generation, signature, execution_class, code_lease }. Plans and execution use the same immutable RegistrySnapshot. Compilation emits resolved slots, not name strings; registry changes invalidate actual callers and invalidate negative lookups that could now bind.
Metadata declares argument/reference semantics, volatility, async behavior, thread/apartment affinity and effects. Unknown extension behavior is conservative. Pure native calls may run on workers; VBA project state normally belongs to one ordered owner. Async completion tickets include input/binding/invocation generations and discard stale results.

CalcVBA exposes neutral load-project, enumerate-public-procedures/signatures, resolve-entry, register-type-library and register-host-interface operations. It owns no worksheet, Range, UDF registration or Excel error mapping.
DNA's glue generates a cached typed shim per procedure signature. For two Doubles, the hot route is resolved plan slot → generated coercion/ABI shim → typed JIT entry with a runtime-environment pointer and scalar arguments. No names, per-call libffi preparation or intermediate spreadsheet Value enum. Reuse activation storage; Variant/ParamArray/ByRef remain explicit marshalled cases.
Reload publishes a new registry snapshot. Running calls pin old code and project state; new calls use new bindings. Retire code only when plans/activations release leases. Signature changes require rebinding, not overwriting a pointer in an old ABI slot. Module procedures remain procedures; their small registration/call interface does not require manufacturing COM objects.
DNA owns the Application/Workbook/Worksheet/Range/WorksheetFunction object library and its type-library source. Generate descriptors, ABI stubs and bindings from one definition. Typed VBA receivers resolve interface/slot/signature at bind time; the interpreter invokes that slot and the JIT emits a typed indirect vtable call.
On Windows this includes real IUnknown identity/lifetime, QueryInterface, ABI-correct strings/arrays, ByRef writeback, HRESULT/error mapping and apartment rules. IDispatch remains necessary for genuinely dynamic receivers, after early binding works in both runtimes. Microsoft's [dual-interface contract](https://learn.microsoft.com/en-us/windows/win32/com/dual-interfaces) distinguishes these access paths.
Reference counting removes the arbitrary permanent Range table, but cycles still require teardown/weak ownership. Object identity and deleted/disconnected workbook behavior are explicit. Worksheet calls get tracked snapshot reads and limited effects; macros use validated host commands and ordered events.
Never hold publication locks across extension calls. A worker needing the extension owner yields. If a VBA callback discovers a missing prerequisite, preserve a resumable activation or evaluate it synchronously in the owning invocation with cycle detection; do not replay stateful VBA or deadlock while messaging the blocked host actor.
XLL/COM adapters reuse call bindings and object services with their own ABI codecs. Agents use the same commands/queries as skins. Future sandboxed add-ins use batch-oriented typed interfaces, not an RPC for every arithmetic operation.

Keep NumericMode::Fast and Exact(target) as explicit choices; retain the current Fast default. Exact selects an algorithm/CPU behavior target, with platform admission determined by evidence. Excel build/platform/CPU are always capture provenance; do not fork algorithms per build without a measured contradiction to the owner's stable-version assumption.
Fast retains the plan's cross-platform determinism contract: pinned portable numeric operations and conversion policy, controlled floating-point settings, and no uncontrolled FMA/reassociation. Keep observation-build metadata separate from the semantic target fingerprint; changing a capture label is not a new numeric algorithm.
NumericTarget must distinguish observed Intel/AMD instruction behavior. The briefing's 15/15 AMD observations support a CPU-dependent path, not universal bit-exactness. Native x87 and software extended arithmetic are separate backend capabilities; correctly rounded software transcendental results need not equal hardware instruction results.
Function research lives in offline tooling: CandidateProgram, explicit precision/store/constant/branch/loop nodes, candidate hashes, exact-bit witnesses and elimination records. Every new answer eliminates inconsistent programs; zero survivors means the hypothesis space is wrong. Higher match ratios cannot justify a product patch.
Use the OxFunc method's [candidate vocabulary and elimination loop](../../../OxFunc/docs/SMART_SEARCH_AND_ACTIVE_LEARNING_LOOP.md), with the briefing's stricter prohibition on fitted corrections overriding its scoring/fitting passages. Freeze survivors before independent tests; preserve observationally equivalent alternatives and uncertainty. Finite witnesses do not prove Excel's exact source program.
Promotion delivers a comprehensible implementation of the identified program plus compact regression witnesses into CalcFunc. Search engines, fitted thresholds, winner-selection tables and large experimental corpora do not become runtime dependencies. Whole-function Exact availability and evidence status remain separate from a selected mode label.

| Profile | Admitted execution |
|---|---|
| Windows | Native engine/pool, evidence-backed numeric targets, typed VBA interpreter/JIT, full COM and Windows add-in adapters as compatibility work is completed. Unsupported members remain explicit. |
| Linux | Same semantic engine, native VBA interpreter/JIT and DNA-provided typed object interfaces; no general Windows COM references. Numeric admission is target-specific, not inferred from Linux/x86 alone. |
| Browser | Same semantics in a yielding worker, typed VBA interpreter and portable host-interface tables; no general COM or direct filesystem access. Optional worker pool; interpreter remains usable without shared memory. Browser compilation would emit/instantiate wasm, not use a native machine-code JIT. Exact requires a demonstrated backend or an explicitly selected remote execution service. |

## 5. Decisions for the owner

1. **Meaning of no code cross-dependencies.** Recommend allowing only DNA's calc-vba glue to depend on a small, versioned, spreadsheet-neutral CalcVBA hosting API crate, with no reverse dependency. This preserves independent ownership and supports efficient typed entries. If independence means no Cargo edge at all, use the same neutral descriptors through a versioned C ABI on native and a wasm-specific interface; accept the packaging and marshalling work explicitly. COM remains the object ABI, not a requirement to turn module procedures into objects.
2. **Reference CPU policy for Exact.** Recommend an explicitly selected, persisted target, with locally available targets clearly described and no silent Intel/AMD substitution. Keep Fast as the default and record build/platform/CPU on every observation. The owner must choose the reference deployment/profile for published Exact claims; support elsewhere is earned with matching evidence, not inferred from architecture.
3. **Lane priority and scope.** Recommend pausing further UI feature slices that enlarge the current controller/server and pausing further late-bound DNA/VBA integration until the corresponding foundations above replace them. Authorise the existing lanes to spend their next work on these seams. Keep actual distributed deployment and non-Excel language/features unplaced; prepare their contracts now.

Formatting ownership, a strict model beneath skins, early binding in both VBA runtimes, and rejection of fitted numeric corrections are already owner rulings. They require implementation, not another approval round.
