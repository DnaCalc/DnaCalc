## 1. Review of the other drafts

### Opus 5.5

**Adopt.** Its concrete axis-run map, dependency facets, separation of worksheet-time and macro-time object services, and separate UI/protocol/worker compilation boundaries deserve inclusion (`opus-5-5.md:49`, `:63`, `:290`, `:343`). These address actual callers: WhatIfReader forwards environment but omits host facts (`D/crates/calc-engine/src/data_table.rs:308`, `:384`); the current VBA callback reads through the formula evaluator (`D/crates/calc-fml/src/eval/run.rs:1885`). A read-only fixture backend and a command-capable workbook backend can share object definitions without making OneCalc depend on CalcHost.

**Wrong or unverified claims.**

- “An insert splits one page” and the structural-edit bound are proposals without an implementation argument (`opus-5-5.md:65`, `:234`). Current pages are keyed by numeric page row/column, derive offsets from coordinates, and contain sparse input arrays (`D/crates/calc-doc-model/src/cells.rs:41`, `:82`). Retaining their bounded copy-on-write principle is possible; keeping this addressing implementation unchanged while making it axis-keyed is not. A row insertion can intersect pages in many column bands. Count affected axis runs, storage chunks, reference occurrences, order-sensitive consumers and serialized output separately.
- The estimated 9–10 bytes per numeric result is compared with the audit's 600–900 bytes for an entire formula cell (`opus-5-5.md:66`). That comparison omits authored source, bindings, graph, indexes, provenance exceptions and retained file records. Current provenance alone has revision, tick, numeric mode and extra flags (`D/crates/calc-engine/src/result.rs:30`). Present a component budget and measurements, not an implied whole-cell reduction.
- “Values are not dirtied” on VBA reload is too strong (`opus-5-5.md:283`). The supplied product contract says reload starts fresh module state (`D/docs/plan/VBA_UDFS.md:10`, `:22`); it does not establish Excel's full reload/invalidation policy. Keep old displayed values where policy allows, but invalidate their callable/code-state validity and negative name bindings. A `CallableChanged` badge must not coexist with a claim that the old result is current under the new registry.
- The current random implementation is accurately identified, but extending its per-cell key to every effect does not prove compatibility (`opus-5-5.md:244`). It intentionally reproduces draws on retries (`D/crates/calc-engine/src/random.rs:5`). Stateful VBA, repeated calls, iteration and table scenarios need invocation identities and an observed order; the captured VBA contract explicitly records repeated initial calls (`D/docs/plan/VBA_UDFS.md:60`).

**Seams mishandled or left open.**

- A self-edge plus its offset sign covers a simple one-direction recurrence, not arbitrary two-dimensional or mixed-offset dependencies (`opus-5-5.md:79`). A filled recurrence can be acyclic at member level but cyclic if collapsed into an ordinary block node. Retain logical member identities and readiness; allow compressed affine edge families and bounded execution chunks without requiring a separately allocated graph node per member.
- `merge_edit` and “only what an edit invalidates is discarded” need a commit check against the new snapshot (`opus-5-5.md:25`, `:105`). An evaluation may have discovered an INDIRECT target or an absence read not yet installed in the published graph. The old dirty cone alone cannot prove reuse safe. Current code avoids this race by rejecting a revision/generation mismatch (`D/crates/calc-engine/src/recalc.rs:1009`); removing that check requires read/binding/effect validation, not just retaining the result map.
- A `may_spill` index cannot be assumed small (`opus-5-5.md:112`). Unknown array shape can cover a large downstream region; an INDIRECT result or a newly loaded callable can change spill potential. Record conservative reach, conflict ownership and the cost of broadening. Do not publish a previously blank cell as settled while an unresolved candidate can occupy it.
- One presentation authority must distinguish base formatting from conditional overlays. Current CELL facts read base formats (`D/crates/calc-host/src/facts.rs:101`), while CF separately changes number formats (`D/crates/calc-host/src/conditional.rs:439`). Feeding a final CF-rendered answer back into CELL or CF evaluation can create a self-dependency. Embedded font metrics also require a font/version/fallback policy; sharing a table does not alone establish Excel width fidelity.
- Owner-thread mailboxes need a callback protocol: a UDF can request a dirty prerequisite while the coordinator waits for that UDF. Specify resumable activation or nested dependency evaluation with cycle checks, and never replay stateful code. The existing callback is synchronous (`D/crates/calc-fml/src/eval/run.rs:1885`); moving it behind a mailbox changes more than thread placement.

**Owner alignment.** Formatting outside CalcFunc and early binding in both runtimes follow §§4.1 and 4.5. Its `asupersync` treatment follows the revised §4.7. Its default invalidation of all nodes for any semantic-environment change (`opus-5-5.md:317`) falls short of its own facet design. Its build-indexed numeric target (`:196`) should retain build as observation provenance unless evidence contradicts §4.4's stable-version assumption. The schedule contains elapsed-time estimates contrary to the supplied development preference; remove them without replacing them with invented precision. Keep the §4.6 fast-check principle instead of selecting an arbitrary fixed smoke-test count.

### Fable 5.1

**Adopt.** The explicit `Absent(Owner)` service value distinguishes an unsupported facility from a legitimately absent fact (`fable-5-1.md:36`). The snapshot-held callable generation, old-code lifetime, owner-thread affinity and separation of FormulaBlockId from NotebookBlockId should also survive synthesis (`:140`, `:205`, `:235`). The thin-tooling/harness split and native tests of the functional model provide concrete migration work with existing callers.

**Wrong or unverified claims.**

- The same-tick prerequisite invariant is wrong (`fable-5-1.md:88`). Let A1 be a clean previously calculated formula and B1 depend on A1 and an edited literal C1. Recalculating B1 should reuse A1's valid older result. The code deliberately returns `NodeStanding::Published` for an unscheduled prerequisite (`D/crates/calc-engine/src/read.rs:435`, `:455`), and `Calculation` records when an evaluation actually happened (`D/crates/calc-engine/src/result.rs:10`). Either Fable's rule forces unnecessary recalculation or it falsely restamps A1. Use `computed_at` plus dependency-closed `valid_for`; topology alone also does not settle unknown spill conflicts.
- “At most three blocks” applies to a one-dimensional fill, not a rectangular block (`fable-5-1.md:50`). Removing an interior member from a rectangle can require four surrounding rectangles plus the exceptional cell. One unchanged BlockId cannot independently identify every new fragment. Preserve logical member identity across fragment changes and keep storage-fragment identity separate.
- Early cutoff is not “already in the plan key” (`fable-5-1.md:401`). A compilation cache key says nothing about whether a dirty formula's actual inputs or output facets changed. Current `begin_recalc` schedules the dirty closure before evaluation (`D/crates/calc-engine/src/recalc.rs:546`). Cutoff needs input/facet version checks, output comparison, and an effect-aware rule for downstream work. A stateful UDF dependent must still execute after an unchanged upstream result where the captured behavior requires it (`D/docs/plan/VBA_UDFS.md:78`).
- A binary API does not inherently require JS between two wasm modules or dynamic loading everywhere (`fable-5-1.md:338`, `:416`). Calling convention, linking and packaging are separate choices; a static C-ABI interface remains possible. The existing manifest establishes a Cargo/git dependency and native-only JIT selection (`D/crates/calc-vba/Cargo.toml:15`, `:18`), not the alleged inevitability or cost of every alternative. Recommend the glue-only Cargo edge for maintainability and shared descriptors, not an unsupported call-overhead claim.
- Native x86-64 alone does not establish Exact, and a permanent browser “no” is stronger than the evidence (`fable-5-1.md:164`, `:178`). The code already distinguishes software arithmetic from differing software/hardware transcendental results (`D/crates/calc-func/src/ported/excel_numeric/mod.rs:10`). Admission is by demonstrated algorithm/backend/CPU target; portable support can remain incomplete without the architecture excluding it.

**Seams mishandled or left open.**

- Keeping the complete upfront dirty-closure ordering (`fable-5-1.md:84`) preserves the delay before the first visible result. A demanded lane at the end of that preparation does not solve the scaling problem. Maintain necessary/dirty membership and readiness incrementally, with budgeted topology repair; Automatic mode still finishes required background work.
- Cancellation only between nodes (`:94`) leaves a long range scan, array function or recurrence uninterruptible. The current host already drives an unlimited loop (`D/crates/calc-host/src/session.rs:679`); replacing the outer budget does not bound an individual evaluation. Specify evaluator/kernel checkpoints and resumable numerical state, with no promise to preempt arbitrary native extension code.
- “Volatile nodes evaluate once per tick” and unconditional order independence (`:98`) do not cover dynamic reevaluation, iterative invocations or stateful UDFs. Module globals are deliberately retained (`D/crates/calc-vba/src/lib.rs:85`; `D/docs/plan/VBA_UDFS.md:22`). Affinity serializes access but does not select Excel's order or call count. Carry effects and execution obligations independently of value equality.
- Restoring pages/blocks by pointer is not enough for structural undo (`:209`). Engine bindings, ownership, edge indexes and context validity must be restored or patched coherently; old results may be invalid under a new clock or registry. The current rebuild at `D/crates/calc-host/src/command.rs:447` is expensive but handles that coherence. Replace it with an inverse engine patch plus validated result reuse.
- The single `Presentation` returned to both CF and CELL repeats Opus's base-versus-effective-format ambiguity. The wire also needs sequence/base versions, dictionary retention, stale-interest rejection and bounded subscriber queues; a style table “once per revision” can itself cause large resend costs.

**Owner alignment.** Explicit service absence, formatting outside CalcFunc and the early-binding priority follow §§4.1 and 4.5. Its acceptance of §4.7 is correct. “No fitted coefficient ... without an Identified row” (`fable-5-1.md:170`) needs stronger wording: a label cannot authorize a fitted correction under §4.4; legitimate constants must belong to the identified program. A separate research repository is an option, not a correctness requirement. Blanket freezes, fixed suite sizes and elapsed-time schedules should become dependency-ordered, reviewable changes consistent with §4.6 and the user's planning preference.

### Gemini 4 Argon

**Adopt.** The explicit unresolved-spill example, budget checks inside evaluation, retained viewport tiles and extraction of a shared FormulaEditSession are concrete responses to current seams (`gemini-4-argon.md:87`, `:216`, `:227`, `:241`). Keep these mechanisms without treating the proposed renderer, PRNG, tile dimensions or remote transport as settled decisions.

**Wrong or unverified claims.**

- **SUM is not associative.** The proposed `numeric_sum` summaries and O(log P) tree reduction (`gemini-4-argon.md:73`, `:253`) can change bits and overflow/error behavior. The implementation explicitly folds numbers in reading order and specifies error precedence (`D/crates/calc-func/src/catalogue/aggregate.rs:120`, `:142`). As a binary64 counterexample, `(10^16 + -10^16) + 1` is 1 whereas `10^16 + (-10^16 + 1)` is 0; this is a regrouping example, not a new Excel measurement. Keep cardinality/occupancy summaries and only independently justified aggregate summaries. A fixed reduction tree is deterministic but still need not be Excel's program.
- Replacing an alleged shared PRNG is misdiagnosed (`gemini-4-argon.md:217`, `:221`): the engine already creates a per-formula seed/tick/cell stream (`D/crates/calc-engine/src/random.rs:5`, `:19`). Philox would be an algorithm change, not the missing determinism fix. Canonical sheet/row/column ordering of stateful UDFs is also not established by the supplied Excel observations. Pinning a clock and making SCCs atomic does not justify “100% of Excel's calculation semantics” (`:340`).
- The blanket claim that any spill disables parallel recalculation is false (`gemini-4-argon.md:214`). Eligibility checks iteration, cycles, staged spills and tables (`D/crates/calc-engine/src/recalc.rs:739`), but `evaluate_levels` already runs parallel stretches between array formulas and evaluates those anchors in order, falling back on a wait (`:835`, `:850`, `:878`). Preserve and extend this behavior. My draft and the audits also oversimplified it; they need the same correction.
- Updating a template once per unique template is insufficient for structural edits (`gemini-4-argon.md:210`). Members sharing relative syntax can require different transforms when only some source/target pairs cross an insertion. Split the placement domain by that transform and index reference occurrences, including inactive branches. An arbitrary overwrite at B500 also cannot retain the same template/plan as its neighbors (`:209`). The current rewrite contract is explicitly caller-position-sensitive (`D/crates/calc-doc-model/src/structural.rs:35`).
- Its authored FormulaBlock contains `Arc<CompiledPlan>` (`gemini-4-argon.md:94`) even though the draft forbids derived calculation state in the authored model and its crate map gives that model only calc-value (`:19`, `:269`). The proposed type violates both rules. Store syntax/template identity in the model and bound plans in an engine/FML-owned cache; a syntax-only crate or equivalent low-level record contract resolves the dependency.
- Swapping a same-signature function pointer in place on reload (`:234`) is not enough. Code identity, globals, volatility, affinity and dependencies can change without the signature changing. A single evaluation could observe mixed generations, and old code may be unloaded during execution. Keep ABI slot shape reusable, but publish an immutable registry generation with code/state leases and invalidate actual and previously missing bindings. Reload currently starts fresh state (`D/docs/plan/VBA_UDFS.md:10`); type compatibility does not waive that semantic change.
- “Every” LAMBDA resolves to a registry slot at bind time (`gemini-4-argon.md:156`) conflates named external entry points with runtime closures. CalcFml creates captured LAMBDA values and has a distinct `Invoke` instruction (`D/crates/calc-fml/src/eval/mod.rs:290`; `D/crates/calc-fml/src/eval/run.rs:437`). Preserve that distinction while allowing specialization of known call targets.
- Software ext80 is necessary for some targets, not sufficient proof of portable Exact (`gemini-4-argon.md:184`, `:349`). The existing backend commentary specifically describes transcendental differences (`D/crates/calc-func/src/ported/excel_numeric/mod.rs:10`). The browser Wasm JIT, zero-allocation typed path and dynamic loadability “by construction” are targets, not established capabilities: today's browser selects the interpreter, and the DNA bridge allocates converted arguments (`D/crates/calc-vba/src/lib.rs:80`, `:139`). `repr(C)` alone specifies neither loader/versioning nor object/array lifetime and error rules.
- `usize` being 32-bit on wasm is a representation limit, not evidence that this code silently truncates dimensions (`gemini-4-argon.md:77`). `ArrayShape::cell_count` uses checked multiplication and construction checks the backing length (`D/crates/calc-value/src/value.rs:114`, `:138`). Fixed-width wire shapes are useful, but checked allocation lengths and chunking are still required. Likewise, current CellPages are sparse input arrays, not dense CalcValue pages (`D/crates/calc-doc-model/src/cells.rs:82`).

**Seams mishandled or left open.** Parallel data-table scenarios need demonstrated effect independence, not just immutable input overlays (`gemini-4-argon.md:123`). An authored edit changes the fixed epoch, so carrying results forward requires validation of every observed facet, not only the old forward cone. A time-slice is a delivery boundary, not proof that its results are settled. “Unchanged” shard messages must include validity/topology/effect facts; equal bits and shape alone do not discharge downstream UDF calls. RaptorQ/Arrow do not define snapshot agreement, lease retirement, duplicate replies or cross-partition SCC/spill arbitration. These belong in the design before selecting a network encoding.

**Owner alignment.** The summary-tree SUM conflicts directly with §4.4's operation-order requirement. Promotion after 100% of probes (`gemini-4-argon.md:185`) remains insufficient identification of the program, and policing commit wording (`:249`) is not semantic enforcement. The implementation phase that enables distributed shards and `Unbounded64` (`:317`) exceeds the briefing's Excel implementation scope without a new owner placement. Keep non-grid participant identities available without weakening Excel coordinate checks. Its `asupersync` boundary follows §4.7; library version, browser support and overhead statements are inherited research findings, not measurements made by this review. Fixed frame-time and zero-allocation promises need evidence.

## 3. Changes to my position, and positions I retain

**I change the following.**

1. **Withdraw my licence objection.** `gpt-astra-6.md:259` is obsolete and contradicts BRIEFING §4.7. `asupersync` may be read, modified and used for this project. Include the rider pointer in notices; isolate the dependency and maintain a simple non-concurrent path. Evaluate it for coarse orchestration and deterministic test scheduling against the existing serial/pool options. The supplied research distinguishes stable default features from nightly-only ergonomic features; do not turn that into a blanket nightly requirement. No counsel condition or capability installation is needed for this review.
2. **Make the foundational mechanisms explicit.** My draft already had validity, interest epochs and publication units, but not a sufficiently concrete maintained necessary set, height/readiness queue, replayable interest input, or axis-run map. Add those with conservative dynamic-topology handling, per-facet cutoff and counter checks; do not leave them as “incremental and indexed.”
3. **Bring visible feedback forward.** I put representation migration ahead of budgeted work and partial publication (`gpt-astra-6.md:234`). Start the context/registry contract and resumable host loop first, then deliver a small validated publication slice on existing scalar nodes while shared-formula/axis migration proceeds. Both consume the same new identity/validity contracts. Keep dynamic conflicts grouped until supported; count that broadening. A comprehensive storage rewrite should not postpone the first correct visible result indefinitely.
4. **Permit a separate calc-format implementation crate.** Principle §4.1 forbids formatting in CalcFunc; it does not require its Rust source to reside physically inside CalcFml. Opus/Fable's extraction can serve the editor and number-text callbacks without importing the evaluator, while CalcFml keeps the formula-facing API. Amend the old plan explicitly if chosen. Do not introduce a second format engine or make CalcFunc depend on it.
5. **Share the numeric substrate with research.** Opus's product-level numeric operations and candidate interpreter using the same precision/store vocabulary reduce transcription mistakes. Extract a crate only when kernels and the lab both use it; keep candidate search and bulk witnesses outside the product dependency closure. My original placement in CalcFunc need not be permanent.
6. **Correct the parallel-spill description and strengthen rendering tests.** Retain the existing mixed scalar/array parallel behavior described above. Add a concrete RenderPlan and semantic browser interface instead of only promising renderer independence. Keep testable geometry separate from glyph rasterization and accessibility behavior.

**I retain the following against the alternatives.**

- **Validity is stronger than a tick.** Keep original computation provenance, validate reused results against input/binding/effect versions, and publish coherent bundles. Do not equate per-value publication with exposing speculative intermediate evaluations. Pinned save/query views and completion events remain distinct from viewport delivery.
- **Members, storage regions and tasks are different.** Keep compressed member identities, affine dependencies, sparse exceptions and independently bounded execution. Stable axis IDs do not make reference transformation, formula source preservation or genuinely large edits free. Keep Excel coordinate validation; use separately keyed non-grid participants for the long-term ambition.
- **Excel observations constrain optimizations.** Preserve arithmetic/store order, required stateful calls, scenario identities and target-specific numerical admission. Software ext80, immutable inputs, a fixed PRNG seed or a canonical ordering each solve only part of that problem. Do not promote a fitted algorithm because a witness set has zero mismatches.
- **One authority with typed local adapters.** Keep DNA-owned object definitions separate from the VBA runtime and available to OneCalc; macros use the host command route, worksheet UDFs get tracked reads and restricted effects. Share descriptors, not mutable runtime state. Pin reload generations/code leases and specify callback reentrancy. A neutral Cargo dependency is my recommendation, not a prerequisite for efficient early binding.
- **Readiness for scale is not permission to ship a cluster now.** Specify transferable snapshots, logical IDs, bounded chunks, leases and completion frontiers; prove the contract with real local/worker traffic. Do not select RaptorQ, a distributed runtime, a new reference language, or an unbounded grid on the strength of a type sketch.
- **Keep the inner loop proportionate.** Consolidate rules, split tooling dependencies, retain behavioral tests and replace representation-specific assertions as their mechanisms change. Do not delete generation tests before replacement assertions establish the new publication contract. Measure metadata and irregular graphs, not just a favorable compressed fill.

## 4. Proposed consensus and genuine open choices

**Converge on these concrete points.**

1. One explicit FEC assembles caller, references, tracked facts, locale/numeric policy, effects, callable snapshot and execution control. Catalogue declarations and runtime tokens drive invalidation; overlays replace only their intended service.
2. One formatting engine outside CalcFunc, with purpose-specific number-text APIs and shared base presentation facts. Conditional overlays remain separately versioned. OneCalc remains engine/document/host-free and shares editor/session behavior with DNA Calc.
3. Preserve lossless formula source plus shared relative templates, axis-run identities and logical member identity. Bound plans are derived. Add affine/rectangle edges and compressed results without collapsing member readiness or numeric operation order.
4. One scheduler supports maintained dirty/necessary sets, bounded stepping, interest reprioritization and fair completion. Keep a sequential implementation. Dynamic reads, spills, SCCs and tables determine safe publication units; values, edges and ownership commit together.
5. Carry computation provenance and validated freshness separately. Record interest/effect inputs for replay, and record or canonicalize publication scheduling when identical streams are required. Save, explicit fresh queries and Calculate events have declared completion scopes.
6. Use one typed command/query model under all skins and automation adapters. Keep model-owned view/interaction state, semantic focus, neutral projections, bounded tile deltas and sequence/dictionary recovery. RenderPlan and real browser interaction tests make rendering replaceable.
7. DNA owns the Excel object library; CalcVBA stays spreadsheet-neutral. Prioritize actual typed slot calls in interpreter/JIT and formula-to-JIT shims, then extend members. Registry snapshots, code/state leases, effects and callback readiness are part of that call contract.
8. Identify numerical programs offline, preserve operations/precision/stores and CPU target evidence, and admit Exact only where supported. No reassociated SUM summaries, argument-only caching of stateful UDFs or witness-score-based fixups.
