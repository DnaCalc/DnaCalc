## 1. Inventory and classification per suite

There are four dispositions. Each is checked by section 4.

- **Covered**: DnaCalc already asserts the same fact. The entry names the covering test, the
  oracle section or the corpus.
- **Obsolete**: the test is about something DnaCalc left behind on purpose. That covers the
  tree-reference language, the dual-profile model, OxCalc's consumer layer, the OxFml/OxFunc
  seam (FEC/F3E, surface dispatch, adapters, registry metadata for the seam), replaced harnesses
  (OxReplay, OxXlPlay bundles, TraceCalc, dnacalc-conform, OxDoc transcripts and profiles,
  OneCalc's verification bundle) and Lean/TLA+ models. Lean and TLA+ models have no Rust tests;
  they are listed as left behind.
- **Port**: the test holds something DnaCalc does not yet assert: an Excel fact, an edge case, a
  regression guard, or a property or differential. The entry names its batch (J1 to J19,
  section 3).
- **Deferred**: the test belongs to a feature an open bead owns. The entry names that bead, and
  the bead must cite the legacy path at the pinned commit (section 4).

## 2. What a ported test looks like

### 2.1 Where it lands (extend, never duplicate)

| Kind of legacy test | Lands in |
|---|---|
| A function's value for given arguments (an Excel fact) | **An oracle row**, never a new oracle workbook. The row goes into a new section of the catalogue oracle: `crates/calc-func/tests/fixtures/catalogue/sheet-jnt_<topic>.txt`, added to `$FormulaSheets` in `make-catalogue-fixtures.ps1` after the sections above it. The workbook is regenerated and committed; the new sheet is awaiting capture until `cargo xtask capture --pending` captures it (that sheet alone; every other sheet's capture stays valid), and is judged by `cargo xtask corpus --oracle`. |
| A formula-language fact that needs only constants | The catalogue as well, in its own section beside `sheet-dcb1l_language.txt`. |
| A formula-language fact that needs defined names, tables, LAMBDA names or sheets | A new section of `crates/calc-fml/tests/fixtures/make-fixtures.ps1` and its oracle, driven through the `Book` harness in `tests/acceptance/l1.rs`. |
| A kernel or evaluator contract with no Excel value (an injected random provider, the batch invoker's order, laziness seen through an observer, a lossless parse round trip) | A unit test inline in the source file that owns the code (`#[cfg(test)] mod tests`) in calc-func or calc-fml. |
| Recalculation correctness after edits | An edit script in `crates/calc-host/tests/incremental.rs`. Its oracle is the fresh open of the same package with the same edits, so it asserts no hand-written value. |
| Graph structure (cycle groups, name and span edges) | Inline tests in `crates/calc-engine/src/graph.rs` or `recalc.rs`. |
| Reference rewriting on insert and delete | `crates/calc-fml/src/reference/transform.rs` tests. Each rule is cited through an Excel measurement added as a section of `crates/calc-host/tests/fixtures/d2/make-structural.ps1`. |
| Conditional formatting results | `crates/calc-host/tests/conditional.rs`, with the facts measured by a new section of `dc_6yw/make-cf.ps1`. |
| Package reading and writing | `crates/calc-doc/tests/d1_oxdoc.rs` and `tests/fixtures/d1/oxdoc/` (shared with dc-nn9). |
| Editor and grid UI behaviour | Inline tests in `apps/dna-onecalc/src/editor.rs` and `formula_field.rs`, or `apps/dna-calc/src/grid/*.rs`. |

### 2.2 Portable by default

- Every ported Rust test is portable. It carries the pair
  `#[cfg_attr(not(target_arch = "wasm32"), test)]` and
  `#[cfg_attr(target_arch = "wasm32", wasm_bindgen_test::wasm_bindgen_test)]`, embeds its data
  with `include_bytes!`/`include_str!`, and touches no file system.
- A test is native-only only when it drives Excel, PowerShell or the file system, for example a
  check that a generator reproduces a committed workbook byte for byte. It keeps `#[test]` with a
  `/// Native-only: <reason>` line.
- Oracle rows are not cargo tests. They run wherever the corpus comparison runs.

### 2.3 An Excel value is cited, never written by hand

1. **The rule.** A test that asserts what Excel computes must take the expected value from an
   Excel reading in the repository: an oracle row with its committed capture, or a capture read
   through `calc_verdict::CaptureRecord`, as `tests/dc_xrxb_support/mod.rs` does. It never takes
   it from a literal copied out of a legacy test, a documentation page or a calculation done by
   hand. A legacy expectation is a hypothesis, not evidence.
2. **How a legacy case gets checked.**
   - The case's formula, inputs and legacy expectation are written as an oracle row.
   - The oracle is captured in Excel on this machine.
   - The corpus comparison judges calc-func against Excel's value.
   - If the legacy expectation disagrees with Excel, Excel wins. The batch's close note lists the
     disagreements: those legacy tests were wrong, and nothing asserts their value.
   - If calc-func disagrees with Excel, the row counts as a failure in the corpus summary (pass is
     matched Excel; fail is mismatched + refused, over all formula cells). It goes into one
     root-cause bead per batch of mismatches: dc-zmk, dc-uar or dc-j9k, or a new bead per root
     cause. The batch is not held open to fix it, unless the fix is small and inside its time.
3. **Inputs that must be exact.** W111 rows carry binary64 inputs that Excel's formula bar would
   round to 15 digits. J1 extends the catalogue line format so that a row can carry its inputs as
   cell values: a formula line followed by tab-separated typed inputs, which the generator
   writes as `<v>` constants with 17 significant digits in columns A to C of the row. The
   formula refers to those cells.
   - J1's first step is a probe row that confirms Excel keeps such a `<v>` exactly.
   - An omitted argument is written as an empty argument (`F(,x)`). An empty-cell argument is a
     reference to an empty cell.
   - This is one extension of the one generator, not a second generator.
4. **Import the readings, keep their environment.** OxFunc's captured answers (W111, the oracle
   cache and the W109 banks, in the evidence repository OxFunc-Evidence) are Excel readings and
   part of the project's Excel record (owner, 2026-10-30). They are imported as they were read,
   each with the Excel build, platform, bitness and CPU its capture recorded (all on one Windows
   host with an AMD Ryzen 7 4800H; builds 19929 to 20430, or unknown where the capture did not
   say). A reading is taken as valid across Excel builds by default: the record is not rechecked
   row by row on every build. `cargo xtask witness judge` detects conflicts instead: when two
   readings of the same function and inputs disagree under different builds or platforms, it
   reports a version or platform difference with both readings kept
   (`crates/calc-func/witness-differences.tsv`), never overwriting one with the other, and the
   difference is followed by a targeted recheck of that function on the builds and platforms at
   hand, recorded the same way. New readings and rechecks come through calc-oracle-excel's bulk
   witness mode, so new captures stay in one capture lineage. The catalogue rows of J1 to J3 are
   still added where a function needs a formula-level check (argument coercion, references,
   arrays), which the bit-pattern banks do not exercise.
5. **Contract tests** assert DnaCalc's own interfaces, not Excel values, and need no citation.
   A legacy test that mixes the two is split. RANDBETWEEN with a provider at 0 giving the bottom
   is a contract test; `RANDBETWEEN(1.5,1.2)` giving `#NUM!` becomes an oracle row.

### 2.4 How a batch works

1. **Triage, case by case, at the pinned commit.**
   - For a function case, look for the formula in the oracle sources (`sheet-*.txt`,
     `prefix-*.txt`, `make-fixtures.ps1`).
   - For other cases, look for a DnaCalc test asserting the same fact.
   - Count covered, obsolete and to port. Classifying by family name alone does not count.
2. **Port.** Rows go into the batch's own section. Tests go into the files of section 2.1. Each
   section header or test doc comment says
   `Ported from <Repo>@<commit>:<path> (<test names>)`.
3. **Measure.** Run `cargo xtask corpus --oracle` before and after, then `cargo test` for the
   touched crates. Portable additions also run under `cargo xtask check --wasm` at the next
   milestone sweep.
4. **Close** with the counts (triaged, covered, obsolete, ported, rows added), the corpus summary
   before and after, the legacy expectations Excel contradicted, and the mismatch beads.
5. **Record the dispositions** in this plan's section 1 table: one line per group, giving the
   commit or bead.

## 4. When a legacy suite counts as reviewed for retirement (dc-jnt)

A suite (OxFunc, OxFml, OxCalc, OxDoc, DnaTreeCalc with DnaOneCalc, OxXlPlay, OxReplay) counts as
reviewed, and stops holding up its archive under dc-jnt.4, when all of the following hold:

1. **Complete inventory.** Its section 1 table accounts for every test at the pinned commit. The
   group counts add up to the total from a stated count command (for example
   `git ls-files '*.rs' | xargs grep -c '#\[test\]'` at the commit), recorded with the number.
2. **One disposition per group, each checkable.**
   - *Covered* names a DnaCalc test, an oracle section or the corpus.
   - *Obsolete* names the reason from BULK_PORT_PLAN §2 or the replaced harness.
   - *Ported* names a closed batch bead and its commits.
   - *Deferred* names an open bead whose text cites the legacy paths at the pinned commit, so the
     archived repository can be found from the tracker alone.
3. **Its batches are closed.** Each close note gives the counts, the
   `cargo xtask corpus --oracle` summary before and after (pass and fail over all formula cells),
   the legacy expectations Excel contradicted, and the mismatch beads filed.
4. **One sample check.** The batch's read-only review agent (AGENTS.md step 5) samples ten tests
   from the suite's *covered* and *obsolete* groups. For each, it confirms that the named cover
   asserts the same fact, or that the reason holds. A wrong sample sends that group back to
   triage.

Mismatches that ported rows expose do not block retirement. They are counted failures owned by
root-cause beads, and the archive keeps the legacy test readable. Deferred groups do not block it
either, provided point 2 holds.

**Order that follows from this:**

1. OxReplay and OxXlPlay are reviewed once J15 has taken the table scenario list, or at once if
   the list is recorded on J15's bead.
2. DnaOneCalc follows with DnaTreeCalc.
3. OxDoc follows J16 and dc-nn9.
4. OxFml follows J5, J12 and J13.
5. OxCalc follows J14 and J15.
6. OxFunc comes last (J1–J4 and J6–J11).
