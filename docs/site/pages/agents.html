Agents

Built so an agent can check its own work

An agent that edits a spreadsheet needs three things: a way to read the model, a way to run it, and an honest answer when something is not supported. DNA Calc gives the same answers to an agent as to a person.

What an agent can use today

  • Run a workbook. dnacalc recalc, get, set and diff write one JSON object with --json, and the exit status says whether every formula cell matched. See the engine.
  • Typed refusals. A formula the engine does not model returns a refusal that names what is missing. It is never a silent wrong number, and it is counted as a failure.
  • Provenance on every value. A cell read back says whether it was calculated by this engine or read from the file.
  • Readable documentation. /llms.txt indexes this site, and guides and articles have Markdown editions. The Handbook has a JSON record for each function, with its behaviour and evidence.
  • Links that carry a formula. {{explore:=XLOOKUP(3,{1,2,3},{"a","b","c"})}} opens that formula in Formula Explorer. The formula travels after the # and is not sent to a server.
  • An open repository. The source is MIT-licensed, and AGENTS.md states the working rules, the checks and the honesty rules that agents and people follow in it.

Designed, not yet built

The view architecture gives an agent two separate lanes, so that a change to how a workbook looks can never change what it calculates.

  • Looks. A theme, a layout or an App page is JSON data. It is validated, tried on, and kept or discarded. Accepting it changes no cell.
  • Model. An agent proposes cell changes as units. A person sees the exact cells each unit writes, accepts some or all, and undoes them one at a time.
  • A trail in the file. What an agent proposed and what was accepted is recorded in the workbook's view part, and can be turned off.

These follow milestone M6 of the skin architecture. This page changes when they are published.
